# Contributing to Awesome Speculative Decoding

Thank you for helping keep this list accurate and current! This project aims to be the most comprehensive, correctly-linked collection of **speculative decoding** research.

## Scope

A paper qualifies if **speculative drafting, its verification, or the theory/serving of speculative decoding is a first-class contribution** — e.g. a new drafter architecture, a verification/sampling scheme, a tree/topology construction method, an adaptation to a specialized target (MoE, multimodal/VLM, speech, diffusion, reasoning), a serving/system, or theory/benchmark. Papers that merely *use* an LLM (with no SD contribution) are out of scope.

## How to Add an Entry

Provide:

- **Title** — exact, matching the arXiv abstract page (method-name prefix included).
- **arXiv ID** — `YYMM.NNNNN`, verified to resolve on `https://arxiv.org/abs/<id>`.
- **GitHub** — the *official* repo link, only if it is named on the abstract page or project site. Use `/` if there is no public code — **never guess a URL**.
- **Year / Venue** — e.g. `ICML 24`, `NeurIPS 25`, `arXiv`.
- **One-line** — ≤22 words on the concrete contribution (no marketing fluff).

Place the row in the correct section (see the Table of Contents), sorted by year descending.

## Verification Bar

Every link must be **live**:

- **arXiv IDs**: must resolve to the titled paper on `arxiv.org/abs/<id>`.
- **GitHub URLs**: must return HTTP 200 and be the authors' official repo (follow redirects).
- **Web/project URLs**: must resolve and the title must match.

Fabricated or dead links will be rejected. If you are unsure of an ID, leave the entry out rather than guess.

Open a PR editing `README.md` and add a one-line rationale in the PR description for the section placement.

## Maintainer Notes

The initial comprehensive list was generated by a 24-agent survey+verify pipeline (2026-07-13): 10 sub-area survey agents self-verified arXiv IDs, followed by a verification pass that fetched each abstract page for title-match + GitHub harvesting, then a second pass on the cross-referenced additions. `_work/` holds the working data and is kept out of the published tree (see `.gitignore`).

Thank you for helping keep the frontier accurate.
